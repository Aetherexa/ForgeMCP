## Lifecycle policy

| State | Liveness | Readiness | Dependency checks run |
| --- | --- | --- | --- |
| Created | down | down | no |
| Starting | up | down | no |
| Started | up | up only when all checks pass | yes |
| Stopping | up | down | no |
| Stopped | down | down | no |

Liveness describes lifecycle availability only, not process responsiveness.
Failed startup retains the existing Created/retry behavior. Failed disposal
retains the existing Stopped/error behavior. Active MCP calls still drain before
owned resource cleanup. Health never starts/stops an application or blocks calls.

## Explicit provider

`createApplicationHealth(app, { checks, timeoutMs })` returns `liveness()` and
asynchronous `readiness()` methods. Dependency checks are caller-owned closures
or objects implementing `HealthCheck`; no implicit service resolution occurs.
Definitions and method bindings are captured at construction. Mutable dependency
state remains provider-owned. Duplicate or whitespace-only names are rejected.

Checks execute concurrently per invocation; reports preserve registration order.
Default timeout is 1000 ms per check. Overrides must be integers from 1 through
2147483647 ms. Error and invalid-result reports use safe codes, never raw provider
objects or exceptions. Probe result objects, arrays and reports are frozen.
The lifecycle is rechecked after probes, preventing stale readiness during drain.

Each invocation is independent and performs fresh probes: there is no cache,
single-flight coordination, scheduler or background state. Timeouts bound only
asynchronous observation; they do not interrupt synchronous work or cancel I/O.
Providers must bound their own I/O. Health checks are not application executions
and shutdown does not wait for them. A probe started before shutdown may finish
later with a down report; timers are cleared and late rejection is consumed.

## Transport/privacy boundary

No implicit HTTP listener or MCP tool is registered. Applications decide exposure
and authorization. Reports contain only health kind/status, lifecycle state,
check names/status and optional failed/timeout/invalid-result codes. Application
check names must be safe operator labels, not secrets.

## Validation

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm release:verify
pnpm package:smoke
pnpm typecheck
pnpm lint
pnpm format
pnpm test:coverage
```

Unit tests cover every lifecycle state, ordering, failure privacy, deadlines and
late rejection, definition snapshots, concurrent observations and configuration
validation. Lifecycle integration covers startup retry and failed disposal.
Official SDK in-memory tests expose a health tool explicitly, retain normal calls
when dependencies are down, and verify readiness drops during graceful drain
while liveness stays up until exactly-once cleanup completes. CI must also pass
dependency security, CodeQL and SonarQube Cloud before merge.

## Non-goals

Automatic HTTP/MCP endpoints, authorization policy, process watchdog, event-loop
lag measurement, cancellation, retries, caching, scheduling, metrics emission,
arbitrary diagnostic data and transport-specific HTTP status mapping.

# v0.4 Sprint 6 — OpenTelemetry completed execution adapter

Tracked in #99. Acceptance requires green CI, security and Sonar before merge.

## Scope

- Optional `@forgemcp/telemetry-otel`, leaving core/application vendor-neutral.
- Real OpenTelemetry completed SERVER spans, count counter and duration histogram.
- Explicit W3C remote-parent correlation, canonical Forge IDs and safe labels.
- Official MCP concurrency, success/failure, privacy and unchanged cleanup.
- Package exports, packing, release verification, coverage and documentation.

`createOpenTelemetrySink({ tracer, meter, acceptRemoteParent })` accepts
caller-owned OpenTelemetry providers. No global provider, context manager or
propagator is registered; exporter setup, flush and shutdown remain caller-owned.
Wrap it with `createExecutionTelemetryListener` and attach before execution.
Spans use the original start/end times and safe OK/ERROR statuses, with no raw
exception descriptions. `forge.execution.id` always preserves the canonical
Forge ID, independently of the OpenTelemetry trace/span IDs. Only finite numeric,
boolean and string attributes are copied; objects, arrays and propagation fields
are omitted. Explicitly selected strings can still contain secrets: allowlist
only trusted operator metadata. Metrics retain only tool name and execution status.

## Incoming MCP context

Remote parents require all three explicit choices:

1. `captureTraceContext: true` on `createForgeMcpServer` copies string request
   `_meta.traceparent` and `_meta.tracestate` into dedicated execution attributes.
2. Select `traceparent` and `tracestate` in the telemetry listener's
   `executionAttributeNames` (never select all `mcp.meta`).
3. Set `acceptRemoteParent: true` on the OpenTelemetry sink.

MCP context capture and parent acceptance default to false. The official W3C
propagator validates fields; malformed/zero identifiers produce root spans.
Each record starts from `ROOT_CONTEXT`, preventing ambient/cross-call parents.
No baggage is propagated. Trace state is passed to the parent context only.
Incoming trace context is untrusted correlation, not identity or authorization;
applications decide which clients may supply it and choose sampler policy.

These are completed spans emitted after execution cleanup, not live tool-body
context. Automatic outbound propagation, child spans inside tools, HTTP endpoints,
OTLP exporter presets and automatic instrumentation are outside this sprint.

## Validation

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm release:verify
pnpm package:smoke
pnpm typecheck
pnpm lint
pnpm format
pnpm test:coverage
```

Real in-memory OpenTelemetry exporters verify timestamps, statuses, parent trace
and span IDs, trace state, count and duration aggregates, invalid parents and
privacy. Official SDK client/server tests run overlapping calls with different
remote trace IDs and Forge IDs, preserve MCP request/session correlation, tool
results, failure handling and request cleanup. Existing stdio and lifecycle tests
remain required. Provider failures remain observational; status failure still ends
the span and does not skip the listener's remaining measurements.

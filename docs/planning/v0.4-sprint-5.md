# v0.4 Sprint 5 — Runtime diagnostic snapshots

Tracked in #98. Acceptance requires green CI, security and Sonar before merge.

## Scope

- Aggregate, immutable application-local snapshots and portable contracts.
- Lifecycle state, active execution count, completed count and failed count.
- Official MCP overlapping success/failure validation, request cleanup and drain.
- Duplicate/unmatched event handling, privacy, public exports and package smoke.

Create one `createRuntimeDiagnostics()` provider per application and attach its
`listener` with `builder.observe(...)` before startup. `snapshot()` returns fresh
frozen values without input, result, errors, metadata, tool names or execution IDs.
Only currently active IDs are retained internally; terminal events remove them.
Counts are cumulative for the provider lifetime, including startup retry. Lifecycle
termination clears active tracking but preserves totals. Duplicate starts and
terminal events are ignored. Active calls remain active through request cleanup.

This is an observation of the event stream, not an authoritative admission API.
Late attachment misses prior events. Listener ordering can expose intermediate
observations during synchronous event delivery. Do not share a provider between
applications or feed synthetic events into a production listener. There is no
history, background sampling, endpoint, exporter or process health measurement.

## Validation

Run the repository checks listed in Sprint 6. Unit tests cover every lifecycle
transition and aggregation; runtime tests hold request disposal during stop;
official MCP tests validate overlapping success/failure without payload exposure.

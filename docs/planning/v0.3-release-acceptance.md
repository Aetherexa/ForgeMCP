# v0.3 Release Acceptance

**Status:** in progress.

Tracked by issue #69.

## Goal

Move the completed v0.3 Configuration and Dependency Management implementation to a release-ready `v0.3.0` main commit before any v0.4 Production Operations work begins.

## Release boundary

This acceptance item prepares the repository for the existing tag-driven GitHub Release workflow.

It does not publish packages to npm.

## Required release state

- root workspace version: `0.3.0`;
- `@forgemcp/core`: `0.3.0`;
- `@forgemcp/application`: `0.3.0`;
- `@forgemcp/mcp-server`: `0.3.0`;
- workspace dependency links remain `workspace:*`;
- changelog contains a dated `0.3.0` section plus a fresh `Unreleased` section;
- public package entry points smoke-test key v0.3 runtime exports;
- README and roadmap identify the release-acceptance state.

## Public surface smoke coverage

The release smoke test must load built package entry points and verify representative runtime exports across the milestone:

### Core

- `LifecycleState`;
- `createServiceToken`;
- `ServiceNotFoundError`.

### Application

- `ForgeApplicationBuilder`;
- `ForgeConfiguration`;
- `EnvironmentConfigurationSource`;
- `ServiceDisposalError`;
- `MissingModuleDependencyError`;
- `CircularModuleDependencyError`.

### MCP server

- `createForgeMcpServer`;
- `serveForgeMcpStdio`.

The smoke test complements TypeScript compilation and package tarball generation; it is not intended to enumerate type-only exports.

## Acceptance gates

The release-ready PR must pass:

1. frozen-lockfile install;
2. release metadata consistency verification;
3. build;
4. built package entry-point smoke test;
5. package tarball generation;
6. typecheck;
7. lint;
8. format;
9. tests and coverage thresholds;
10. dependency security;
11. CodeQL;
12. SonarQube Cloud Quality Gate.

## Tag behavior

After the release-ready PR is merged, the final `main` commit is the only valid commit to tag as `v0.3.0`.

The existing release workflow will then:

- verify the tag equals the package version;
- rerun release gates;
- pack all three public packages;
- create/update the GitHub Release and attach tarballs.

npm publishing remains disabled.

## Deferred from v0.3

Release acceptance does not expand the milestone scope. These remain deferred:

- session/connection dependency scopes;
- user-created child scopes;
- optional/conditional module dependencies;
- automatic constructor injection;
- decorators/reflection metadata;
- execution cancellation/timeouts;
- disposal retries;
- observability/telemetry work planned for v0.4.

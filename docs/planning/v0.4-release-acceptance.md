# v0.4 Release Acceptance

Tracked in #104. Repository release-ready only after green gates and merge.

## Release contents

All four public packages and the root manifest use `0.4.0`. The milestone includes
application/execution diagnostics, structured logging with stderr JSON Lines,
portable completed execution telemetry, application health/readiness/liveness,
aggregate runtime snapshots, and the optional OpenTelemetry adapter.

The packages are ESM-only and target Node 24+. Core and application do not depend
on a vendor SDK. MCP stays in its adapter package; OpenTelemetry stays optional.

## Acceptance commands

```sh
pnpm install --frozen-lockfile
pnpm run clean
pnpm build
pnpm release:verify
pnpm package:smoke
pnpm package:verify
pnpm typecheck
pnpm lint
pnpm format
pnpm test:coverage
```

`package:verify` packs every public package and installs the resulting tarballs
outside the workspace. It validates published dependency versions, runtime/type
export targets and public lifecycle/observability behavior. Runtime dependencies
require registry access. Installation scripts are disabled. Temporary files are
removed on completion or failure. CI and the release workflow run this check
after a clean build so old generated chunks cannot contaminate release tarballs.

Required remote gates: Quality gates, Dependency security, CodeQL and an actual
SonarQube Cloud scan. A skipped scan is not release acceptance.

## Publication boundary

After merge, select the accepted main commit for `v0.4.0`. The existing tag-driven
workflow reruns validation and creates a GitHub Release containing four tarballs.
Creating that tag requires a maintainer with authenticated tag-write access.
This readiness item does not publish to npm or claim the tag already exists.
The historical v0.3 tag remains separately visible in #69 and must target its
original release-ready commit, not current main.

## Explicit limitations

Completed spans support incoming W3C parent correlation, but do not establish
live tool-body context or automatic outbound propagation. Exporter lifecycle is
caller-owned. Health and snapshots register no endpoint or MCP tool automatically.
Timeout/cancellation, retries, execution limits and authentication/authorization
remain v0.5 work. Do not describe v0.4 as a stable production v1.0 release.

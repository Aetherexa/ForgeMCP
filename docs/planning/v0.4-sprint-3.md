## Scope

`createExecutionTelemetryListener` consumes the existing diagnostic fact stream.
On a matched execution terminal event it hands a completed `ExecutionSpanRecord`
to `ExecutionTelemetrySink.writeSpan` and two `ExecutionMetricRecord` measurements
to `recordMetric`: `forge.execution.count` (1) and `forge.execution.duration` (ms).
A caller-owned adapter can translate these into its tracing/metrics provider.
No provider SDK or exporter dependency is installed by ForgeMCP.

Spans carry canonical Forge IDs, tool name, timestamps, cleanup-inclusive duration
and ok/error status. Arbitrary execution attributes require explicit selection;
framework attributes are included. Metrics use only tool name and status as
labels: no Forge IDs, MCP IDs, selected attributes, raw payloads or exception text.
Use one listener instance per application and attach it before execution.

## State and failure semantics

The listener tracks only active executions. A terminal event removes its state
before provider delivery; unmatched/duplicate terminal events are ignored.
Duplicate starts preserve the first start. Application stopped/start-failed/
stop-failed events clear incomplete executions. No synthetic spans are emitted.
A lost terminal event retains its start until application reset/shutdown; no
background timers or eviction policy are added. Complete runtime diagnostics
normally provide terminal events for all executions.

Each synchronous provider callback is independently isolated, so a span failure
does not suppress count/duration measurements. Provider batching, network I/O,
retries, flush and shutdown remain caller-owned. Callbacks must be fast.
Records and attribute objects are shallow-frozen; Date values and nested selected
application data are copied/owned according to the same shallow snapshot policy
as diagnostics/logging. Consumers must not mutate them.

## Validation

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm release:verify
pnpm package:smoke
pnpm typecheck
pnpm lint
pnpm format
pnpm test:coverage
```

Tests cover out-of-order concurrent completion, failure status, safe attribute
selection, immutable top-level records, invalid-duration fallback, lifecycle
reset, missing/duplicate events and throwing providers. Official SDK calls prove
result/error semantics, MCP supporting IDs, scoped cleanup before spans, and
exactly-once application resource disposal. CI must also pass dependency security,
CodeQL and SonarQube Cloud before acceptance.

## Non-goals

OpenTelemetry SDK bindings/exporters, distributed parent propagation, live span
objects, sampling, automatic exception serialization, metric aggregation,
application lifecycle metrics, health endpoints and exporter lifecycle management.
Health remains the next operations slice; resilience/security belong to v0.5.
